# دليل تعديل الموقع من GitHub (بدون برمجة)

تعدّل ملفات الموقع من المتصفح على github.com، ثم يبني GitHub الموقع وينشره وحده. لا تحتاج تشغيل `build.bat` ولا أي برنامج.

## 1) ماذا يحدث عند كل حفظ؟

1. افتح الملف على github.com ← اضغط أيقونة القلم `Edit this file` أعلى يمين الملف ← عدّل ← الزر الأخضر `Commit changes...` ← اترك الخيار `Commit directly to the main branch` ← اضغط `Commit changes`.
2. فور الحفظ يبدأ GitHub Actions وحده: يبني الموقع (`node build.mjs`) ثم ينشره. يستغرق عادةً من دقيقة إلى دقيقتين، وبعدها حدّث صفحة الموقع بـ `Ctrl+F5`.
3. تابع التقدّم من تبويب `Actions` أعلى المستودع. أول سطر في القائمة هو آخر عملية:
   - دائرة صفراء: جارية الآن.
   - علامة صح خضراء: نجحت وتحدّث الموقع.
   - علامة x حمراء: فشلت، ولم يتغيّر الموقع (يبقى على نسخته السابقة السليمة).
4. قراءة رسالة الخطأ العربية عند الفشل: `Actions` ← اضغط السطر الأحمر ← اضغط `build` من القائمة اليسرى ← افتح الخطوة الحمراء `بناء الموقع (node build.mjs)`. ستجد سطرًا يبدأ بـ «خطأ:» يليه اسم الملف ورقم السطر وتلميح. صحّح ذلك الملف واحفظ من جديد. أشهر الأسباب: فاصلة أو علامة اقتباس ناقصة في ملف `.json`، أو قيمة `status` غير `available` و`soon`، أو اسم صورة شارة غير موجودة.

## 2) تغيير حالة دورة (متاحة الآن / قريبًا)

1. افتح `site` ← `data` ← `courses.json`.
2. اضغط أيقونة القلم `Edit this file`.
3. ابحث (`Ctrl+F` داخل المحرر) عن معرّف الدورة: `capm` أو `pmp` أو `pmi-rmp` أو `pmi-acp` أو `pmi-cp` أو `pmi-pmocp`. ثم غيّر السطر الذي تحته:
   - `"status": "available"` تعني متاحة الآن.
   - `"status": "soon"` تعني قريبًا.
4. لا تغيّر شيئًا آخر. الكلمة بحروف صغيرة وبين علامتي اقتباس `" "`.
5. `Commit changes...` ← `Commit changes`، ثم تابع تبويب `Actions` حتى تظهر علامة الصح الخضراء.

## 3) إضافة مقال في المدونة

> **[قسم مؤجَّل: تُستكمل مع مهمة المدونة]**
>
> المسار المخصص للمقالات هو `site/content/blog/`. صيغة ملف المقال وخطوات إضافته ستُوثَّق هنا عند اكتمال مهمة المدونة. إلى ذلك الحين لا تضف شيئًا في هذا المجلد، ولا تحذف ملف `README.txt` الموجود فيه.

## 4) استبدال شارة ATP السنوية

الطريقة الأسهل، بنفس الاسم:

1. افتح `site` ← `assets` ← `badges`.
2. `Add file` ← `Upload files` ← اسحب الصورة الجديدة بعد تسميتها `atp-2026.png` تمامًا (نفس الاسم ونفس الحروف).
3. `Commit changes`. تحلّ الصورة الجديدة محل القديمة.

الطريقة الثانية، باسم جديد (مثل `atp-2027.png`):

1. ارفع الصورة بالخطوات نفسها أعلاه.
2. افتح `site/data/site.json` ← القلم ← غيّر `"atpBadge": "atp-2026.png"` إلى الاسم الجديد، وغيّر `"year"` إلى السنة الجديدة ← `Commit changes`.

## 5) تعديل نصوص الصفحات

- لكل صفحة ملف في `site/src/pages/`: `index.html` (الرئيسية)، `about.html`، `courses.html`، `pmi.html`، `pmp.html`، `capm.html`، `trainer.html`، `faq.html`، `contact.html`، `blog.html`، `privacy.html`، `terms.html`.
- **آمن تعديله:** الكلمات العربية والإنجليزية الظاهرة بين الوسوم، مثل `<p>هذا نص</p>` و`<h2>عنوان</h2>`. وكذلك قيمتا `title=` و`desc=` في السطر الأول من الملف (عنوان التبويب ووصف محركات البحث).
- **لا تلمس:** بقية السطر الأول (`slug=` و`nav=`)، وأي شيء بين `{{` و`}}`، والوسوم نفسها وخصائصها (`class=` و`href=` و`src=` و`id=`)، وكتل `<script>`. ولا تحذف علامتي `<` و`>`.
- صفحات المنصة (`account.html` و`dashboard.html` و`admin.html`) ليست للتعديل اليدوي.
- النصوص والروابط المشتركة (واتساب، حسابات التواصل) في `site/data/site.json`: غيّر القيمة بين علامتي الاقتباس فقط.
- **لا تعدّل أبدًا أي شيء داخل مجلد `dist/`:** هو ناتج تلقائي يُعاد توليده عند كل نشر فتضيع تعديلاتك.

## 6) التراجع عن خطأ

- إن فشل البناء (علامة x حمراء) فالموقع لم يتغيّر أصلًا؛ صحّح الملف واحفظ.
- للتراجع عن تعديل ظهر فعلًا في الموقع، من المتصفح:
  1. افتح الملف ← زر `History` أعلى اليمين ← عند النسخة التي قبل الخطأ اضغط أيقونة `<>` ← اضغط `Copy raw file` لنسخ المحتوى القديم.
  2. ارجع إلى الملف الحالي على `main` ← القلم ← `Ctrl+A` ثم `Ctrl+V` ← `Commit changes`.
- أو من GitHub Desktop: تبويب `History` ← بالزر الأيمن على الحفظ الخاطئ ← `Revert Changes in Commit` ← `Push origin`.
- لا يضيع شيء: GitHub يحتفظ بكل النسخ السابقة.

## 7) ما الذي لا يُرفع أبدًا؟

- اعتبر كل ملف في المستودع علنيًا يقرؤه أي شخص، بكل نسخه السابقة.
- **الملفات الخالية من الأسرار (آمنة):** كل ما في `site/`، ومنه `site/data/site.json` (فيه عنوان مشروع Supabase والمفتاح العام `sb_publishable_...` أو `anon`، وهما علنيان بطبيعتهما ومحميان بسياسات RLS)، وملفات `supabase/migrations/*.sql`، ومجلد `docs/`.
- **لا ترفع أبدًا:**
  - مفتاح `service_role` أو أي مفتاح يبدأ بـ `sb_secret_`.
  - كلمة مرور قاعدة بيانات Supabase، أو كلمة مرور أي حساب.
  - ملفات `.env` أو `creds.json` أو أي ملف فيه `password` أو `token`.
  - رموز GitHub الشخصية (`ghp_...`).
  - بيانات المتدربين (أسماء، بريد، هواتف، ملفات CSV).
- إن رفعت سرًّا بالخطأ فحذف الملف لا يكفي، لأنه يبقى في `History`. غيّر السر فورًا من مصدره (Supabase ← `Project Settings` ← `API Keys` أو `Database`) ثم أبلغ من يدير المشروع.

## 8) إعداد GitHub Pages (مرة واحدة، تفعلها بنفسك)

1. افتح المستودع على github.com ← تبويب `Settings` ← من القائمة اليسرى `Pages`.
2. تحت `Build and deployment` ← `Source` ← اختر `GitHub Actions` (وليس `Deploy from a branch`).
3. اذهب إلى `Actions` ← من القائمة اليسرى اختر `نشر الموقع على GitHub Pages` ← `Run workflow` ← `Run workflow`، لتجربة أول نشر.
4. بعد نجاحه يظهر رابط الموقع في `Settings` ← `Pages` وفي ملخص التشغيل.
5. إن وُجد الملف القديم `.github/workflows/static.yml` (أنشأه GitHub تلقائيًا) فاحذفه: افتحه ← أيقونة سلة المهملات `Delete file` ← `Commit changes`. وجوده مع النشر الجديد يجعل عمليتين تنشران معًا وقد تُنشر نسخة قديمة.
6. ملاحظة: Pages مجاني للمستودعات العامة `Public`. المستودع الخاص يحتاج اشتراكًا مدفوعًا.

## 9) تحذير مهم: الموقع يعمل على جذر النطاق فقط

- الموقع يكتب روابطه بالشكل `/assets/...` و`/pmi/`، أي من جذر العنوان. لذلك لا يعمل سليمًا إلا إن كان عنوانه جذرًا مثل `https://اسم-المستخدم.github.io/` أو نطاقك الخاص.
- **حالتك الآن:** اسم المستودع `ahmedaldeib91/Ahmed-aldeib-platform` وليس `ahmedaldeib91.github.io`. فعنوانه سيكون `https://ahmedaldeib91.github.io/Ahmed-aldeib-platform/`، وهذا «موقع مشروع» (project site). ستظهر الصور والخطوط والتنسيقات وبعض الروابط مكسورة، لأن `/assets/...` ستُطلب من `https://ahmedaldeib91.github.io/assets/...` وهو غير موجود.
- **الحل الأول: إعادة تسمية المستودع (مجاني).** `Settings` ← `General` ← خانة `Repository name` ← اكتب `ahmedaldeib91.github.io` ← `Rename`. يصير العنوان `https://ahmedaldeib91.github.io/`. بعدها في GitHub Desktop: `Repository` ← `Repository settings` ← `Remote` ← ضع الرابط الجديد `https://github.com/ahmedaldeib91/ahmedaldeib91.github.io.git` ← `Save`. يُشترط ألا يوجد عندك مستودع آخر بهذا الاسم.
- **الحل الثاني: نطاق خاص** (مثل `ahmedaldeib.com`، يُشترى من مسجّل نطاقات). `Settings` ← `Pages` ← `Custom domain` ← اكتب النطاق ← `Save`. ثم عند مسجّل النطاق أضف سجلات DNS:
  - أربعة سجلات من نوع `A` للنطاق الأساسي بالقيم `185.199.108.153` و`185.199.109.153` و`185.199.110.153` و`185.199.111.153`.
  - سجل `CNAME` للاسم `www` يشير إلى `ahmedaldeib91.github.io`.
  - بعد أن يتحقق GitHub (من دقائق إلى ساعات) فعّل `Enforce HTTPS`. يمكن أن يبقى اسم المستودع كما هو.
- **عن الحقل `basePath`:** إن وجدته في `site/data/site.json` (أُضيف يدويًا على GitHub) فلا تعتمد عليه. هو يصلح جزءًا من الروابط فقط (الترويسة والتذييل وصفحات المنصة)، وما زالت بقية الصفحات والخطوط بروابط تبدأ بـ `/`. عند اعتماد الحل الأول أو الثاني اجعل قيمته فارغة: `"basePath": ""`.

## 10) بعد أول نشر ناجح

1. افتح `site/data/site.json` ← القلم ← غيّر `"domain"` إلى عنوان موقعك الحقيقي بلا `/` في النهاية، مثل `"https://ahmedaldeib91.github.io"` أو `"https://ahmedaldeib.com"`. وإن وُجد `"basePath"` فاجعله `""` ← `Commit changes`. (تدخل هذه القيمة في الرابط الأساسي `canonical` وفي `sitemap.xml` و`robots.txt`.)
2. في Supabase: افتح `https://supabase.com/dashboard` ← اختر المشروع ← `Authentication` ← `URL Configuration`:
   - `Site URL`: العنوان الحقيقي نفسه (مثل `https://ahmedaldeib91.github.io`).
   - `Redirect URLs` ← `Add URL` ← أضف `https://ahmedaldeib91.github.io/account/` وأضف أيضًا `https://ahmedaldeib91.github.io/**` ← `Save`. (استبدل العنوان بعنوانك الحقيقي إن اخترت نطاقًا خاصًا.)
   - بدون هذه الخطوة تفشل روابط تأكيد البريد وإعادة تعيين كلمة المرور لأنها تُرسل إلى عنوان خاطئ.
